# 明部の色調整（`--warm` / `--tint`）の実画像検証

**日付**: 2026-08-28（ティント軸の検証を追記）
**きっかけ**: 実写真（AnimeStudio 出力の 4K PNG）で `--warm` を振っても「全然変わらない」という報告。
**結論**: **実装のバグを1件発見して修正した**。`AlternateHeadroom` を固定値にしていたため、表示時のゲインが本来の約 1/3 に薄まっていた。

## 入力画像

AnimeStudio 出力の 4K PNG（画像はリポジトリに含めていない）。

- 寸法: 3840×2160、16bit PNG、9.3MB
- 平均リニア輝度: **0.4333**（かなり明るい画像）
- 明部加重 `t > 0.1` の画素: **26.42%**
- 明部加重 `t > 0.5` の画素: **9.11%**

`t` は合成カーネルの明部加重 `smoothstep(0.5, 1.0, L)`（`L` はリニア輝度）。色温度調整はこの `t` に比例して効くため、**`t` がほぼ 0 の中間調・暗部には作用しない**。

### リニア輝度ヒストグラム

```
  0.0-0.1:  7.87% ###
  0.1-0.2:  9.25% ####
  0.2-0.3: 11.83% #####
  0.3-0.4: 16.66% ########
  0.4-0.5: 15.20% #######
  0.5-0.6: 13.06% ######
  0.6-0.7: 13.28% ######
  0.7-0.8:  9.41% ####
  0.8-0.9:  2.40% #
  0.9-1.0:  1.04%
```

明部（0.5 超）は約 39% あるが、`t` が有意に立つ 0.7 超は **12.85%** と少なめ。効果が出る面積そのものは限られる画像だった。

---

## 発見した不具合: `AlternateHeadroom` の固定値

### 症状

自前生成した 3ch カラーゲインマップ（`--warm` 非ゼロ時）の `AlternateHeadroom` を **3.25 固定**にしていた。一方、CoreImage の自動生成（`--warm 0`、1ch）は**画像ごとの実測値**を入れる。

| 条件 | GainMapMax | AlternateHeadroom |
| --- | --- | --- |
| `hdrCurve --warm 0`（従来・1ch） | 1.103 | **1.103** |
| `hdrCurve --warm 0.5`（修正前・3ch） | 3.250 | **3.250** |
| `hdrML --warm 0`（従来・1ch） | 1.849 | **1.830** |
| `hdrML --warm 0.5`（修正前・3ch） | 3.250 | **3.250** |

### なぜ効かなくなるか

ISO ゲインマップの適用は、表示側のヘッドルーム `H` に応じた重み付きで行われる。

```
w    = log2(H) / AlternateHeadroom     （BaseHeadroom = 0 のとき）
実効ゲイン = 2^(w × GainMapMax × v)     （v は 0…1 の正規化ゲイン）
```

`v = log2(g) / GainMapMax` なので、`AlternateHeadroom = GainMapMax` のとき整理すると:

```
実効ゲイン = g ^ (log2(H) / GainMapMax)
```

**`GainMapMax` が実際の最大ゲインより大きいほど、指数が小さくなり全体が弱まる**。表示ヘッドルーム 2倍（`log2(H) = 1`）の画面で、ゲイン 2倍を持つ画素がどう表示されるか:

| 条件 | GainMapMax | 指数 | 実効ゲイン |
| --- | --- | --- | --- |
| 従来（1ch） | 1.103 | 0.91 | **1.88倍** |
| 修正前（3ch） | 3.250 | 0.31 | **1.24倍** ← 約 1/3 |
| 修正後（3ch） | 1.305 | 0.77 | **1.71倍** |

HDR 効果そのものが 1/3 に薄まり、色温度の差も同じ比率で圧縮される。これが「全然変わらない」の主因だった。

### 修正内容

`ColorGainMap.measureMaxLog2` を追加し、**画像ごとに実際の最大 log2 ゲインを測って** `GainMapMax` / `AlternateHeadroom` に設定するようにした。

- 合成 HDR と SDR ベースの比の log2 を `CIAreaMaximum` で 1×1 に縮約して最大値を取る
- `CIAreaMaximum` は出力を [0,1] にクランプし得るため、1/8 にスケールしてから最大を取り、掛け戻す
- 結果は `maxLog2Floor`(0.25) 〜 `maxLog2Ceiling`(3.25) にクランプ（実測失敗時は 3.25 へフォールバック）

## 使い方と推奨値

```sh
gainforge -x --warm 0.5 写真.png      # カーブ法 + 明部を少し暖色に
gainforge -m --warm 0.5 写真.png      # ML/LUT 法でも同じ
```

- **0.3〜0.5**: 「言われれば分かる」程度の自然な暖かみ
- **0.75〜1.0**: はっきり分かる暖色寄り（強明部で R/B +17〜23%、色温度換算でおよそ -800K 相当）
- **0（既定）**: 完全に無効。出力は現行実装とバイト単位で一致する

### この画像で効果が控えめに見える理由

1. `t` が有意に立つ輝度 0.7 超の画素が **12.85%** しかない（効果面積が限られる）
2. 効果は **HDR ヘッドルームのある画面でのみ**現れる。SDR 表示や、ヘッドルームを絞った状態では基本的に見えない
3. 内部係数は強度 1.0 で `k = 0.15` と控えめに設定している（`HighlightWarmth.maxCoefficient`）

もっと強くしたい場合は `Sources/GainForgeCore/ColorGainMap.swift` の `HighlightWarmth.maxCoefficient` を上げる（0.25 まで上げると強明部の R/B は概ね +40% 程度になる見込み）。

### 副作用として把握しておくこと

暖色シフトは R を持ち上げるため、画像の最大ゲインがわずかに増える（この画像で 1.103 → 1.305、+18%）。ヘッドルームが十分な画面では影響ないが、**ヘッドルームの小さい画面では HDR 効果が数%〜15% ほど控えめになる**。完全展開時の輝度は不変なので、これは ISO ゲインマップの仕様上の性質。

## 追加検証: ティント軸（マゼンタ⇔グリーン）

色温度軸（`--warm`）に続けて、2 軸目の **`--tint`（正でマゼンタ、負でグリーン）** を追加した。
G を下げた分を R/B で取り戻す**輝度中立**の配分（係数 `0.7152/(0.2126+0.0722) ≈ 2.5112`）なので、
明部の明るさを変えずに色だけが寄る。

同じ入力画像で、明部（`t > 0.5`、約 25 万画素）の平均値を測定した結果:

| 条件 | R/G | B/G | R/B | 明部輝度 Y | AltHeadroom |
| --- | --- | --- | --- | --- | --- |
| tint 0（無効） | 1.1049 | 0.9512 | 1.1616 | 0.9631 | 1.103 |
| tint 0.3 | 1.1524 | 0.9925 | 1.1611 | 0.9639 | 1.167 |
| tint 0.5 | 1.1852 | 1.0207 | 1.1611 | 0.9642 | 1.208 |
| tint 1.0 | **1.2690** | **1.0940** | 1.1600 | 0.9651 | 1.306 |
| tint -0.5（グリーン） | 1.0284 | 0.8843 | 1.1629 | 0.9623 | 1.146 |
| warm 0.5 + tint 0.5 | 1.2454 | 0.9684 | **1.2860** | 0.9725 | 1.313 |

読み取れること:

1. **マゼンタ方向にきちんと寄る**。tint 1.0 で R/G が +14.9%、B/G が +15.0%。R と B が揃って上がり
   G だけが相対的に下がる = マゼンタ。
2. **2 軸が直交している**。ティントを最大まで振っても R/B 比（＝色温度軸）は 1.1616 → 1.1600 と
   ほぼ動かない。逆に `warm 0.5 + tint 0.5` では R/B が 1.286（色温度が効く）かつ B/G が 0.968
   （ティントが効く）で、両方が独立に乗る。
3. **輝度中立が機能している**。明部の輝度 Y は 0.9631 → 0.9651（**+0.2%**）で実質不変。
   マゼンタに寄せても明部が暗くならない。
4. `AlternateHeadroom` は色温度軸と同様、画像ごとの実測値に追随している（1.103 → 1.15〜1.31）。

### 使い方

```sh
gainforge -x --tint 0.4 写真.png                 # 明部だけ少しマゼンタに
gainforge -x --warm 0.5 --tint 0.3 写真.png      # 暖色寄り＋わずかにマゼンタ
gainforge -x --tint -0.3 写真.png                # グリーン方向
```

**0.3〜0.5** が「少しだけマゼンタ」の目安（R/G・B/G が +5〜9%）。内部係数は強度 1.0 で G を 6% 下げ、
R/B を約 15% 上げる設定（`HighlightTint.maxCoefficient = 0.06`）。

## 再現手順

明部（リニア輝度 0.5 超）をある程度含む SDR 画像なら何でも再現できる。

```sh
swift build -c release
for v in 0 0.25 0.5 0.75 1.0; do
  .build/release/gainforge -x --warm $v -o /tmp/gf_warm_$v 入力画像.png
done
for v in 0 0.3 0.5 1.0; do
  .build/release/gainforge -x --tint $v -o /tmp/gf_tint_$v 入力画像.png
done
```

測定は `CIImage(contentsOf:options:[.expandToHDR: true])` を拡張リニア Display P3 で `RGBAf` レンダリングし、入力の明部加重でマスクした画素の平均 R/B 比を取る。ゲインマップの `GainMapMax` / `AlternateHeadroom` は `CGImageSourceCopyAuxiliaryDataInfoAtIndex` → `kCGImageAuxiliaryDataInfoMetadata` から読める。
