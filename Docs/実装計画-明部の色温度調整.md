## 概要

SDR→HDR 合成（`.hdrCurve` / `.hdrML`）で、**明部だけ色温度を下げる（暖色寄りにする）**調整を追加する。
中間調・暗部は無彩のまま、SDR ベース画像も変えない。CLI / GUI の両方から強度を指定でき、**省略時は現行と同一の出力**になる。

- **対象**: 合成経路への per-channel ゲイン（暖色シフト）と、それを保存できる 3ch カラーゲインマップ書き出し経路
- **やらないこと**:
  - **生転写経路（ゲインマップ付き入力）には一切触れない**。画素一致保証を壊さない
  - `.sdr`（8bit SDR 保存）にも効かせない
  - 色相ごとの選択的な色調整（ホワイトバランス以外の色いじり）は対象外
- **関連**: [SDRのHDR化手法の研究.md](SDRのHDR化手法の研究.md) / [仕様.md](仕様.md) / [画面仕様.md](画面仕様.md)

### 事前検証で判明していること（実測済み）

| 検証項目 | 結果 |
| --- | --- |
| 現行 `writeHEIF10Representation(.hdrImage:)` が生成するゲインマップ | **1ch モノクロ**（`L008`・`ChannelMetadata` 1要素）。per-channel の色差は輝度に平均化されて消える |
| ImageIO 低レベル経路で 3ch(32BGRA) ゲインマップを添付 | **finalize 成功**。保存時に 4:2:0 カラー（`420f`）へ変換され色が残る |
| Apple 公式デコード（`CIImage(options:[.expandToHDR:true])`）での展開 | 明部のみ R>G>B（例 x=95%: R=3.75 G=2.61 B=1.82）、中間調は R=G=B のまま |
| ImageIO 経路での 10bit 維持 | 16bit `CGImage` をベースに渡すと `Depth=10`・ゲインマップ保持を両立 |
| ゲインマップ metadata の**自作** | `CGImageDestinationFinalize` が **false**。CoreImage 生成の metadata を借用すれば通る |

## 注意点

- **CoreImage の自動生成では実現できない**。`writeHEIF10Representation(.hdrImage:)` は 1ch ゲインマップしか作らず、per-channel の差は消える。必ず ImageIO 低レベル経路を通すこと
- **metadata の自作は finalize に失敗する**（実測）。CoreImage が生成した metadata を借用する
- **P1-1 の結論**: 借用 metadata を `CGImageMetadataCreateMutableCopy` し、`ChannelMetadata` を**配列タグごと差し替える**と `GainMapMin/Max` を任意設定できる。個別タグへの `CGImageMetadataSetValueWithPath` は構造体配列の中では効かない（`AlternateHeadroom` のような直下のタグには効く）。借用元は 32×32 のダミーで足り、**寸法が違ってもそのまま使える**ため、ベース画像の二重エンコードは発生しない（1 パスで完結）
- **元画像の `Depth` プロパティを引き継がないこと**。8bit JPEG/PNG 由来の `Depth=8` を `CGImageDestinationAddImage` に渡すと、16bit ベースを渡しても出力が 8bit になる（実測でハマった）
- **CIKernel の引数名をカーネル内のローカル変数と衝突させないこと**。`expandHighlightsKernel` には肌色判定用のローカル変数 `warm` が既にあり、引数名を `warm` にするとシャドウイングされて tint が常に誤った値で適用される（コンパイルも通り、実行時も落ちないため発見しにくい）。引数名は `warmTint` にしてある
- ゲインマップは保存時に 4:2:0 へ変換されクロマ解像度が半分になるが、色温度シフトは緩やかなので実害は想定していない。P5-1 で確認する
- 色を振るのは**明部だけ**。既存の色保護（低彩度・肌色）ロジックは維持し、tint は既存の明部加重 `t` に必ず乗せる（中間調に色が乗ると破綻する）
